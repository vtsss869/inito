## 1. What this project is

This is **not a conventional software codebase**. It is a **product-design working folder** for
**Inito** — a home fertility/hormone-tracking product (an iOS app plus reader hardware and test
devices). The owner works as a designer (Figma handle "O0 Valeriia",
`valeriia.tsymbaliuk@ozero.design`).

The folder holds three kinds of material:

1. **Figma source files** (`.fig`) and one FigJam file (`.jam`) — the design source of truth,
   stored here as local copies/exports.
2. **Design-to-code prototypes** — self-contained HTML prototypes of app flows, built to be
   pixel-accurate to the Figma designs.
3. **Prompts, research, and supporting assets** — Markdown prompt specs used to generate the
   prototypes, a research/strategy doc, an HTML deck, SVG icons, and a helper script.

There is **no application build**: no `package.json`, no lockfile, no `node_modules`, no `src/`,
no git repository, and no framework config anywhere in the folder. The HTML prototypes run
directly in a browser with no build step.

## 3. Tech stack & dependencies

There is no package manager or dependency manifest. The stack is defined **inside** the HTML
prototypes and prompt specs:

- **Prototype runtime:** plain HTML/CSS/JS opened directly in a browser. No bundler, no build.
- **React prototypes (as specified in prompts):** React 18 + ReactDOM, Tailwind CSS, and
  Lucide icons, all via CDN (esm.sh / unpkg / cdnjs). JSX via in-browser Babel or precompiled
  inline JS. Target: a single `index.html`.
- **Fonts:** **SF Pro** as the primary UI font, via the Apple system stack
  `-apple-system, BlinkMacSystemFont, 'SF Pro Text', 'SF Pro Display', sans-serif`.
  **Montserrat** (Google Fonts) as a secondary font, used only for the "inito" logo/brand label.
  The prompts explicitly say **never** substitute Roboto or Inter.
- **Placeholder media** in the hand-built prototype: `i.pravatar.cc` (avatars),
  `picsum.photos` (images).
- **Python:** `parse_metadata.py` uses only the standard library (`json`, `xml.etree`).

### Design tokens (extracted from the Figma designs, as recorded in the prompt specs)
These values appear consistently across `claude-code-community-flow-prompt.md` and
`figma-make-community-flow-prompt-v2.md`. They are the canonical tokens for the Community app UI.

Colors:
- `background` `#FFFFFF`
- `surface` `#F2F2F7` (inputs, inactive chips, tag pills)
- `surfaceBlue` `#DDE9FF` (poll option backgrounds)
- `textPrimary` `#26313A` / `rgb(38,49,54)`
- `textSecondary` `#9D9D9D` (placeholders, inactive tabs)
- `textMuted` `#AEAEAE` (timestamps)
- `primary` / blue `#5790FF` (CTAs, links, active tab underline, badges, back arrows)
- `primaryDark` / dark teal `#112D35` (FAB, active Next/Post buttons — not pure black)
- `infoBackground` `#EAF0FF`
- `separator` `#E5E5EA`, `rgba(0,0,0,0.1)`
- `successGreen` `#34C759`, `dangerRed` `#FF3B30`

Type scale (px): caption2 11, caption1 12, subheadline 14, body 15, callout 16, headline 17, title3 20.
Spacing (px): 4 / 8 / 12 / 16 / 20 / 24.
Radii (px): 8 / 10 / 12 / 16 / pill 999 / circle 50%.
Mobile frame: 390×844.

The Figma Make v2 prompt also defines a detailed **motion system** (push/pop navigation timing
and easing, button/chip/toggle/FAB micro-interactions, tooltip and progress-bar animations).

## 7. Relationship between the Figma design system and the "codebase"

- The **`[Design System] Inito.fig`** file is the design source of truth for components, colors,
  typography, and spacing.
- There is **no automated token/code pipeline** in this folder (no exported token JSON consumed
  by code, no Style Dictionary, no Code Connect files, no generated CSS variables).
- The link between design and code today is **manual and prompt-mediated**: design values are
  read out of Figma and hand-transcribed into the prompt specs as explicit tokens (see §3), and
  those prompts drive prototype generation (Claude Code / Figma Make). `parse_metadata.py` is a
  one-off aid from that manual process (parsing a saved Figma metadata dump).
- Practical implication: **design tokens can drift** between Figma and the prototypes because
  they are copied by hand. Treat `[Design System] Inito.fig` as authoritative and the token
  blocks in the prompts as a snapshot.

   produce a pixel-accurate **HTML/React prototype**.
4. Prototypes are reviewed in-browser; the reference screenshot (`feed-screen-reference.png`)
   keeps generation aligned.

## 9. How to run things

- **HTML prototypes** (`prototype.html`, `community-flow-prototype.html`, `Figma-reorg-deck.html`):
  open the file directly in a browser (double-click, or `open <file>.html` on macOS). No install,
  no server, no build. Internet access is needed for the CDN font and placeholder images in
  `community-flow-prototype.html`.
- **SVG icons:** open in a browser or any vector tool; embed directly in HTML.
- **`parse_metadata.py`:** `python3 parse_metadata.py` — but it points at a session-specific temp
  file that no longer exists, so update the `path` variable to a current Figma `get_metadata`
  JSON dump before running.
- **`.fig` / `.jam` files:** open in Figma Desktop / FigJam (they are Figma documents, not
  editable as text).
- There is **no app to `npm run`** in this folder.

## 10. Conventions & constraints

- **Fonts are strict:** SF Pro (Apple system stack) everywhere; Montserrat only for the "inito"
  brand label. Do not substitute Roboto/Inter.
- **Prototypes are single self-contained files** (one `index.html`); dependencies via CDN only,
  no bundler.
- **Pixel fidelity to Figma is the bar** — prompts call out exact colors, radii, button shapes
  (pill, not rectangle), and layout specifics (e.g. FAB dark teal `#112D35`, post cards have no
  background and sit on white separated by a 1px `#E5E5EA` divider, "Step N/N" as a second line
  under the nav title).
- **Mobile frame is 390×844** (iPhone), centered on desktop with a notch/status bar.
- **Design tokens are copied by hand** from Figma into specs — keep them in sync with the design
  system file.
- **Multilingual:** some briefs are in Russian; content may mix EN/RU.
- **Figma access is view-only on the Inito org** — cannot push edits to Inito org files through
  the official MCP with the current seat; the Desktop Bridge (when opened on a file the user can
  edit) is the write path.

## 11. What an AI coding agent should know before modifying this project

1. **This is a design folder, not an app repo.** Don't look for `package.json`, `src/`, tests, or
   a git history — there are none. Don't scaffold a build system unless explicitly asked.
2. **Never edit `.fig` / `.jam` / `.png` as text** — they are binary Figma/FigJam documents and
   large (several are 300 MB–1+ GB). Editing them means using Figma or the Figma MCP tools, not
   file edits.
3. **Treat `[Design System] Inito.fig` as the source of truth** for tokens/components. The token
   blocks in the prompt `.md` files are hand-copied snapshots and may drift.
4. **When generating UI, reuse the established tokens and fonts** in §3 rather than inventing new
   ones; match the pixel-fidelity conventions in §10.
5. **Prototypes must stay single-file and CDN-only** unless the user asks otherwise.
6. **Figma MCP:** the official MCP is read/write via the cloud API but **View-only on the Inito
   org**; the Desktop Bridge plugin (local, WebSocket) is **not connected by default** and must be
   opened in Figma Desktop before its live tools work.
7. **`parse_metadata.py` is not a live tool** — it references a stale temp path.
8. **Respect the existing files.** If asked to build the specified React "New Post" prototype,
   produce a new file; don't overwrite `prototype.html` or `community-flow-prototype.html` unless
   asked.
9. **Confirm intent before large Figma operations** (exports, writes) given file sizes and the
   view-only org seat.
