# Perimenopause symptom logging — research summary

Собрано в рамках дип-ресерча про hot flashes / night sweats логирование для Daily Log.
Источник: research + feature-research сессия, 2026-09-21.

## 1. Клиническая картина (hot flashes / night sweats)

- **Частота**: норма — от нескольких раз в неделю до нескольких раз в день; severe — 4-5/час, 20-30/день (повод к врачу). ~75% женщин испытывают hot flashes в пери/менопаузе, у 25-30% — достаточно тяжело, чтобы влиять на качество жизни.
- **Длительность эпизода**: 1-5 минут (диапазон встречается от 30 сек до 30 мин). Сам период симптоматики в жизни — в среднем 2.5-7 лет.
- **Паттерн по времени суток**: обнаружены два кластера женщин — с пиком утром (04:00–09:59) и с пиком вечером/ночью. У ~трети женщин hot flashes хуже именно вечером. Есть ~12-часовая периодичность (не случайны, кластеризуются).
- **Ночные vs дневные — один и тот же вазомоторный механизм.** Night sweats = "hot flashes occurring during sleep". Greene Climacteric Scale держит их как два *соседних, но раздельных* пункта (item 19 hot flushes, item 20 night sweats) внутри одной вазомоторной подшкалы.
- **Триггеры**: кофеин, алкоголь (особенно вечером), острая/поздняя еда, стресс, тёплая среда, курение, колебания сахара в крови.
- **Сопутствующие симптомы**: потливость, flushing, озноб после эпизода, сердцебиение, тревожность, головокружение.

## 2. Клинический "золотой стандарт" логирования

- **Daily Hot Flash Diary (DHFD)**: считает частоту *по каждому уровню severity отдельно* (mild = 1-2 эпизода, moderate = 3-4, severe = 5+ с потливостью/нарушением сна/тревогой). Частота фактически зашита внутрь severity-категорий, а не отдельное свободное поле.
- **HFRDIS**: не про ощущение severity, а про interference — насколько симптом помешал в 10 сферах жизни, шкала 0-10.
- **Greene Climacteric Scale**: "bothered by" 4-точечная шкала (not at all / a little / quite a bit / extremely), hot flushes и night sweats — два соседних вопроса.
- **Consensus Sleep Diary (CSD)**: золотой стандарт для сна — принципиально **retrospective, заполняется утром** про прошедшую ночь, в течение часа после пробуждения.

## 3. Надёжность self-report

- **Дневные эпизоды**: человек в сознании во время эпизода → count относительно надёжен.
- **Ночные эпизоды**: систематический обзор concordance между self-report и объективным измерением (sternal skin conductance) дал **kappa = 0.03** для самого факта "был ли хоть один эпизод ночью" — по сути нулевое согласие. Люди физически не осознают/не помнят многие ночные эпизоды, особенно без полного пробуждения.
- **Вывод**: точный count ночью — низковалидные данные. Днём — ок.

## 4. Friction / completion-rate данные

- Numeric entry (написать число) — самый большой источник friction в daily-логах; bucketed quick-select (one-tap) снижает его.
- Explicit confirmation dialogs / лишние шаги = abandonment. "One tap" — золотой стандарт для habit/symptom трекеров.
- Interval-contingent diary design (спрашивать каждый день, включая "не было") даёт полный denominator для частотных метрик, но без явного гейта нельзя отличить "симптома не было" от "юзер не залогировал".
- Первый вопрос формы должен быть простым/nonthreatening (survey design) — сложные/детальные вопросы (time-of-day breakdown) лучше не в начале.

## 5. Конкурентный ландшафт (что логируют кроме severity)

| Апка | Особенность |
|---|---|
| MenoCool | 14 доказательных триггеров, анализ окна 2-6ч до эпизода, protective factors |
| Trace | one-tap логирование, фокус на триггерах, PDF-отчёт для врача |
| Clue (Perimenopause mode) | hot flashes + night sweats как отдельные из 14 peri-специфичных пунктов, Oura integration |
| Stella | 34 симптома, Oura Ring (sleep/readiness/HRV) |
| Balance | 30+ симптомов, без детализации по времени/триггерам |

Никто не делает полноценный time-of-day breakdown с count+severity на блок — это уже сильная сторона нашего вайрфрейма.

## 6. Выводы для UX-решений (обоснование для вариантов)

**A. Yes/No-гейт не нужен как отдельный шаг.**
Убрать отдельный Yes/No-вопрос; вместо него — "None / Not today" как первый чип в самой severity/count шкале (по аналогии с уже существующей карточкой Night Sweats, где "None" — один из чипов, а не отдельный шаг). Сохраняет explicit negative response (нужно для частотных метрик), но убирает лишний шаг/тап.

**B. Number (count) — да, но не свободный numeric input.**
Заменить "How many?" free number field на bucketed quick-select (0 / 1-2 / 3-4 / 5+, один тап) — снижает friction, сохраняет данные. Это ближе к DHFD-логике (частота зашита в категории).

**C. Night Sweats — без count-поля.**
Из-за kappa=0.03 (нулевое согласие self-report/objective ночью) — не просить точное число ночью. Оставить только severity (или качественный вопрос "проснулись из-за этого: нет/один раз/несколько раз" как компромисс, не точный счётчик).

**D. Порядок вопросов**: gate (merged into scale) → impact/interference (quality of day) → time-of-day detail (если решили оставить) → count/severity per block. Детализация по времени — самая "дорогая" по recall, должна идти последней, не первой.

**E. Hot Flashes vs Night Sweats — группировать, не сливать.**
Один клинический механизм (vasomotor), но разный контекст логирования: hot flashes — в течение дня, night sweats — ретроспективно утром (как CSD). Рекомендация: визуально сгруппировать в одну секцию "Vasomotor symptoms", но оставить раздельными карточками/вопросами.
